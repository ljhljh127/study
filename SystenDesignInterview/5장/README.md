# 안정 해시 설계
수평적 규모 확장성을 달성하기 위해서는 요청 또는 데이터를 서버에 균등하게 나누는 것이 중요하다. 안정 해시는 이 목표를 달성하기 위해 보편적으로 사용하는 기술이다.  

## 해시 키 재배치 문제

### 1. 기본적인 서버 분배 방식

N개의 캐시 서버에 부하를 균등하게 분산하기 위해 일반적으로 다음과 같은 해시 함수를 사용한다.

$$
\text{serverIndex} = \text{hash(key)} \bmod N
$$

* `key`: 캐시 데이터의 키
* `hash(key)`: 키를 해시 함수에 입력한 결과
* `N`: 서버의 개수
* `%` 또는 `mod`: 나머지 연산
* `serverIndex`: 데이터를 저장할 서버의 인덱스

서버 풀의 크기가 고정되어 있고 데이터가 균등하게 분포한다면 별다른 문제가 발생하지 않는다.

### 2. 문제점: 서버 개수가 변경되는 경우

기존 서버가 장애를 일으키거나 서버 풀에서 제거되면 \(N\) 값이 변경된다. 이로 인해 대부분의 키에 대한 서버 인덱스가 달라지게 된다.

예를 들어, 서버가 4대일 때 특정 키가 서버 2에 저장되어 있었다고 가정하자.

```text
hash(key) % 4 = 2  → 서버 2
hash(key) % 3 = 0  → 서버 0
```

서버가 4대에서 3대로 줄어들면 동일한 키라도 다른 서버를 가리킬 수 있다.

### 3. 발생하는 문제

* **대규모 캐시 미스(Cache Miss)**: 기존 데이터가 저장된 서버가 아닌 다른 서버에 요청하게 된다.
* **서버 부하 증가**: 캐시에 데이터가 없어 원본 데이터베이스에 요청이 집중된다.
* **시스템 성능 저하**: 데이터베이스 부하가 급증하면서 전체 서비스의 응답 속도가 느려질 수 있다.

### 4. 해결 방법: 안정 해시(Consistent Hashing)

이러한 문제를 해결하기 위해 사용하는 기술이 **안정 해시(Consistent Hashing)** 이다.

안정 해시는 서버의 추가 또는 제거가 발생하더라도 전체 키 중 일부만 재배치하도록 설계되어 있어, 불필요한 캐시 미스를 줄일 수 있다.


## 안정 해시의 동작 원리

### 1. 해시 링(Hash Ring)

안정 해시는 서버와 데이터 키를 동일한 해시 공간에 배치하고, 이를 원형으로 연결한 **해시 링(Hash Ring)** 을 사용한다.

* **해시 함수**: 서버 이름이나 데이터 키를 숫자로 변환한다.
* **해시 링**: 해시 값을 원형 공간의 위치로 표현한다.
* **서버 선택**: 데이터 키의 위치에서 시계 방향으로 이동하며 처음 만나는 서버를 선택한다.

예를 들어, 서버 A가 15, 데이터 키 `user:100`이 30, 서버 B가 45에 배치되어 있다고 가정하자. `user:100`에서 시계 방향으로 이동하면 가장 먼저 서버 B를 만나므로 해당 데이터는 서버 B에 저장된다.

### 2. 서버 추가 및 데이터 재배치

서버 D가 해시 링의 35 위치에 추가되었다고 가정하자.

기존에는 `user:100`의 위치인 30에서 시계 방향으로 처음 만나는 서버가 B였지만, 서버 D가 추가되면 가장 먼저 만나는 서버가 D로 변경된다.

따라서 해당 데이터의 담당 서버는 B에서 D로 변경되며, 실제 데이터도 새 담당 서버에서 조회할 수 있도록 재배치해야 한다.

**핵심은 서버가 추가되더라도 모든 데이터가 이동하는 것이 아니라, 담당 서버가 변경되는 일부 데이터만 재배치한다는 점이다.**

### 3. 가상 노드(Virtual Node)

안정 해시를 사용하더라도 서버를 링에 하나의 위치로만 배치하면 서버별 담당 구간의 크기가 달라져 데이터가 특정 서버에 집중될 수 있다.

이를 개선하기 위해 **가상 노드(Virtual Node)** 를 사용한다.

* 하나의 실제 서버를 해시 링의 여러 위치에 배치한다.
* 각 위치는 `A-1`, `A-2`, `A-3`처럼 표현할 수 있으며, 모두 실제 서버 A를 가리킨다.
* 가상 노드를 여러 개 배치하면 각 서버가 담당하는 구간이 여러 곳으로 나뉘어 데이터 분배가 더 균등해질 수 있다.

가상 노드는 실제 서버를 추가하는 것이 아니라, 기존 서버를 해시 링의 여러 위치에 표현하는 방식이다.

### 4. 안정 해시의 장점

* **데이터 재배치 최소화**: 서버가 추가되거나 제거될 때 영향을 받는 일부 데이터만 재배치한다.
* **캐시 미스 감소**: 서버 변경으로 인해 발생하는 불필요한 캐시 미스를 줄일 수 있다.
* **부하 분산 개선**: 가상 노드를 활용하여 서버별 데이터 분배를 더 균등하게 만들 수 있다.

단, 안정 해시가 모든 데이터의 분배를 완벽하게 균등하게 보장하는 것은 아니다. 가상 노드의 개수와 데이터 분포 등에 따라 실제 분배 결과는 달라질 수 있다.
