# 개략적인 규모 추정
개략적인 규모 추정(back-of-the-envelope estimation)은 보편적으로 통용되는 성능 수치로 사고 실험을 해서 추정치를 계산하고, 어떤 설계가 요구사항에 부합하는지 보는 것이다.  
이를 잘하려면 **2의 제곱수, 응답지연 값, 가용성 수치**를 잘 이해하고 있어야 한다.

## 2의 제곱수
- 분산 시스템의 데이터 양은 매우 커질 수 있지만 계산법은 기본을 크게 벗어나지 않는다.
- 최소 단위는 1바이트(8비트)이며, ASCII 문자 하나가 1바이트를 차지한다.

| 2의 x 제곱 | 근사치 | 이름 | 축약형 |
|---|---|---|---|
| 2¹⁰ | 1천 (thousand) | 킬로바이트 | KB |
| 2²⁰ | 1백만 (million) | 메가바이트 | MB |
| 2³⁰ | 10억 (billion) | 기가바이트 | GB |
| 2⁴⁰ | 1조 (trillion) | 테라바이트 | TB |
| 2⁵⁰ | 1000조 (quadrillion) | 페타바이트 | PB |

## 모든 프로그래머가 알아야 하는 응답지연 값
구글의 제프 딘이 2010년에 공개한 수치로, 일부는 지금은 유효하지 않지만 연산 속도를 짐작하는 데 도움이 된다.

| 연산명 | 시간 |
|---|---|
| L1 캐시 참조 | 0.5ns |
| 분기 예측 오류 (branch mispredict) | 5ns |
| L2 캐시 참조 | 7ns |
| 뮤텍스 락/언락 | 100ns |
| 주 메모리 참조 | 100ns |
| Zippy로 1KB 압축 | 10µs |
| 1Gbps 네트워크로 2KB 전송 | 20µs |
| 메모리에서 1MB 순차 read | 250µs |
| 같은 데이터센터 내 메시지 왕복 | 500µs |
| 디스크 탐색 (seek) | 10ms |
| 네트워크에서 1MB 순차 read | 10ms |
| 디스크에서 1MB 순차 read | 30ms |
| 캘리포니아 → 네덜란드 패킷 왕복 | 150ms |

- 1ns(나노초) = 10⁻⁹초
- 1µs(마이크로초) = 10⁻⁶초 = 1,000ns
- 1ms(밀리초) = 10⁻³초 = 1,000µs = 1,000,000ns


**결론**
- 메모리는 빠르지만 디스크는 아직도 느리다.
- 디스크 탐색(seek)은 가능한 한 피하라.
- 단순한 압축 알고리즘은 빠르다.
- 데이터를 인터넷으로 전송하기 전에 가능하면 압축하라.
- 데이터센터는 보통 여러 지역(region)에 분산되어 있고, 센터 간 데이터를 주고받는 데는 시간이 걸린다.

## 가용성에 관계된 수치들
- **고가용성(High Availability)**: 시스템이 오랜 시간 동안 중단 없이 운영될 수 있는 능력
    - 퍼센트로 표현하며, 100%는 한 번도 중단된 적이 없다는 뜻이다. 대부분의 서비스는 99~100% 사이다.
- **SLA(Service Level Agreement)**: 서비스 사업자와 고객 사이의 합의로, 서비스 가용시간(uptime)이 공식적으로 기술된다.
    - 아마존, 구글, 마이크로소프트는 99% 이상의 SLA를 제공한다.
    - 가용시간은 관습적으로 9의 개수로 표시하며, 9가 많을수록 좋다.

| 가용률 | 하루당 장애시간 | 주당 장애시간  | 개월당 장애시간 | 연간 장애시간 |
|---|---|---|---|---|
| 99% | 14.40분 | 1.68시간 | 7.31시간 | 3.65일 |
| 99.9% | 1.44분 | 10.08분 | 43.83분 | 8.77시간 |
| 99.99% | 8.64초 | 1.01분 | 4.38분 | 52.60분 |
| 99.999% | 864.00밀리초 | 6.05초 | 26.30초 | 5.26분 |
| 99.9999% | 86.40밀리초 | 604.80밀리초 | 2.63초 | 31.56초 |

## 규모 추정 공식

### QPS (Query Per Second, 초당 요청 수)
1초에 서버로 들어오는 요청 수. 사용자 수에서 출발해 아래 순서로 구한다.

1. **DAU = MAU × 매일 사용하는 비율**
    - MAU(Monthly Active User): 한 달 동안 활동한 사용자 수
    - DAU(Daily Active User): 하루 동안 활동한 사용자 수
2. **일일 요청량(Requests per Day) = DAU × 사용자 1명당 하루 요청 수**
3. **QPS = 일일 요청량 / 86,400초** (24시간 × 3,600초)

### 최대 QPS (Peak QPS)
- **최대 QPS = QPS × 2**
    - 요청은 특정 시간대에 몰리므로, 피크를 평균의 약 2배로 가정한다.

### 저장소 요구량
- **일일 저장소 = 일일 요청량 × 저장 대상 비율 × 1건당 크기**
- **총 저장소 = 일일 저장소 × 보관 일수**
    - 크기가 압도적으로 큰 항목(예: 미디어)만 계산하고, 작은 항목은 근사치로 생략할 수 있다.

### 계산 흐름
**QPS**  
MAU → DAU → 일일 요청량 → QPS → 최대 QPS

**저장소**  
일일 요청량 → 일일 저장소 → 총 저장소

---

### 예제: 트위터 QPS와 저장소 요구량 추정
> 연습용 수치이며 실제 트위터와는 관계없다.

**가정**
- MAU 3억 명, 50%가 매일 사용
- 1인당 하루 평균 2건 트윗
- 미디어 포함 트윗 10%, 미디어 크기 1MB
- 5년간 보관

**QPS**
- DAU = 3억 × 50% = 1.5억
- 일일 요청량(트윗 수) = 1.5억 × 2 = 3억 건
- QPS = 3억 / 86,400 ≈ 3,500
- 최대 QPS = 3,500 × 2 ≈ 7,000

**저장소**
- 일일 저장소 = 3억 × 10% × 1MB = 30TB/일
- 총 저장소(5년) = 30TB × 365 × 5 ≈ 55PB
